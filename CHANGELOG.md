# Changelog

All notable changes to ac-dlssg are listed here. Versions follow
[Semantic Versioning](https://semver.org/). The release workflow publishes the
section of a version as its GitHub release notes.

## [1.3.0] - unreleased

### Added

- **The installer turns NVIDIA Smooth Motion off for Assetto Corsa** (GitHub issue 10). On a PC with an RTX 40 or RTX 50, `install.bat` reads "Smooth Motion - Enabled APIs" (0xB0CC0875, a bit mask: 1 DX12, 2 DX11, 4 Vulkan; not set means all) in the NVIDIA driver profile that holds `acs.exe` ("Assetto Corsa") and in the global profile. When DX11 is among the APIs in effect, it prints what Smooth Motion is and what it changes, and clears the DX11 bit in that profile only, usually from not set (7) to 5; the global profile and other games stay as they are. NVIDIA's driver settings need administrator rights to change, so Windows asks for this one change. A declined prompt or a failed change is a warning, and everything else is installed. When DX11 is already excluded, nothing changes.
- The change is made by the new driver-profile helper `ac-dlssg-drs.exe`, which the package ships in `files\ac-dlssg` and installs as `<game>\ac-dlssg\ac-dlssg-drs.exe` (KERNEL32 only, no network, `nvapi64.dll` from System32): `smooth-motion status` reads the setting in both profiles without administrator rights, `smooth-motion off` changes it and writes a record, and `smooth-motion restore` puts the recorded state back. Every change is read back from a fresh load of the driver settings; when `off` fails after it saved the change (its read-back, or its result file), the installer reads the profile again and records the change it finds there, so that the uninstaller still restores it. The helper writes its result file sharing read access, so a virus scanner that holds it open does not cost the record. The install and the uninstall clear the downloaded zip's mark of the web from the installed helper before they run it elevated, so that Windows shows its prompt for administrator rights without a SmartScreen warning first. The install manifest (schema 7) keeps the record (`driverProfile`: the profile, the value before, the value written), and every later install keeps it.
- NVIDIA's own "Assetto Corsa" profile only matches an `acs.exe` in a folder named `assettocorsa`, as in every Steam install. Elsewhere the driver can give `acs.exe` the predefined profile of another game (such as "ACS"). The helper leaves such a profile alone (`smooth-motion status` and `off` then exit with code 8), and the installer's warning names it, says why, and gives the steps in NVIDIA Profile Inspector, which then apply to that other game too. A profile the user made is changed as usual.
- `uninstall.bat` restores the setting: it deletes it again when the profile had none, or writes the old value back, but only while the profile still holds the value the installer wrote. A value changed since is left as it is, without a prompt, and the uninstaller says so; a declined prompt or a failed helper is a warning with the steps for NVIDIA Profile Inspector.
- `install.bat -KeepSmoothMotion` skips the step and leaves the driver profile alone; a change an earlier install made stays recorded and is still restored by the uninstaller. The bridge itself still never changes driver settings.
- **Triple screens: diagnostics.** Frame generation does not work on triple screens yet; whether and how it can depends on how CSP lays out its DLSS for the three screens, which only logs from triple-screen setups can show. With `triple_diag=1` under `[debug]` in `ac-dlssg.ini` and Assetto Corsa in triple-screen mode, the bridge proxies the game's swap chain with frame generation off ("triple-screen diagnostics ([debug] triple_diag=1): frame generation stays off; the DLSS calls are logged"), captures nothing, and writes `triple-diag:` lines into `bridge.log` for 300 frames from the first DLSS evaluate: every CSP DLSS evaluate with its feature, its D3D11 context and whether that is the game's device, sizes, render subrect, subrect bases, jitter, MV scale and its Color, Output, Depth and MotionVectors textures with their pointers, and per frame the number of evaluates, those the NGX hook did not count (on a deferred context, or failed, with the result), and the swap chain's size. A DLSS feature created later starts another 300 frames, in up to four such windows in all; a window stops after 3000 evaluate lines, and the session after 6000. When no DLSS evaluate comes in 600 frames, `bridge.log` says so once, with what CSP needs for DLSS in triple-screen mode: Extra FX on, and its "Allow in triple" (`extra_fx.ini` `[BASIC] ALLOW_IN_TRIPLE=1`), whose effective values `bridge.log` lists at start. The CSP app writes CSP's triple-screen layout (`ac.getTripleConfiguration()`) into CSP's log in triple-screen mode. Without the switch, triple-screen mode stays refused as before.

### Fixed

- **NVIDIA Smooth Motion is recognised** (GitHub issue 10). On NVIDIA driver 621.01, RTX 40 and RTX 50 cards, Smooth Motion (the driver's own frame generation, `NvPresent64.dll`) took over Assetto Corsa's swap chain even while the NVIDIA App showed it off, and DLSS-G never started ("DLSS evaluate on another D3D11 device"). The bridge now sees that `NvPresent64.dll` creates the game window's swap chain (it looks for it in the call stack, so it also works through ReShade), passes the game through, and the AC DLSS-G window says "NVIDIA Smooth Motion (the driver's own frame generation) is active for Assetto Corsa, even if the NVIDIA App shows it off. It cannot run with DLSS-G. Run install.bat again to turn it off for AC (or see the README), then restart the game." `bridge.log` has a warning with the fix: run `install.bat` again, or in NVIDIA Profile Inspector set "Smooth Motion - Enabled APIs" (0xB0CC0875) to 5 in the "Assetto Corsa" profile, which clears its DX11 bit. When the game's profile already keeps DX11 out and Smooth Motion is still on, `install.bat` would have nothing left to do, so the window gives the global profile's step instead ("NVIDIA Smooth Motion is still on for AC, though the profile "Assetto Corsa" keeps DX11 out; DLSS-G cannot run with it. In NVIDIA Profile Inspector set Smooth Motion - Enabled APIs to 5 in the global profile ("Base Profile") too, then restart AC."); when `acs.exe` gets another game's predefined profile, it names that profile. `bridge.log` lists the game's profile, whether NVIDIA predefined it, and its Smooth Motion value next to the global one. It also says whether `NvPresent64.dll` is loaded at start, at the first DXGI factory and at the first swap chain, and when Smooth Motion creates its own swap chain on its hidden window. The bridge never changes driver settings.
- **"Cannot find drive. A drive with the name 'F' does not exist."** (GitHub issue 13). `install.bat` stopped when Steam's `libraryfolders.vdf` still listed a library on a drive that no longer exists. Such a library is now skipped and the search goes on with the next one; when the game is found in none of them, the message names the skipped libraries and why (for example `F:\SteamLibrary (drive F: does not exist)`) and asks for `-GameDir`. The same applies to `uninstall.bat`, `collect-logs.bat` and the system report.
- `collect-logs.bat` always writes `collect-logs.txt` and the zip. Before, a documents folder on a missing drive (Documents moved or redirected) stopped it with "FAILED" and no zip at all. Now that is noted as "documents folder not found", and a section that fails for another reason is noted as `FAILED: <section>: <message> (collect-logs.ps1:<line>)` while the other sections are still collected.

### Changed

- **A DLSS-G failure is retried by itself** (a comment on the Steam guide). When Streamline reported a failure status for DLSS-G, or its state query failed, frame generation stayed off until Ctrl+F10 or a resize. The bridge now retries it by itself after 5, 10, 20 and 40 seconds, then once a minute, and `bridge.log` says when the next try comes; a toggle or a resize still retries at once and starts the count over, as does a minute without a failure. Only `eFailResolutionTooLow` and `eFailHDRFormatNotSupported`, which a retry cannot change, still wait for a resize or a toggle. The video memory check already tried again every 60 frames while too little memory was free.
- **The AC DLSS-G window opens by itself once** (Nexus: "the UI does not pop up"). The first time the app runs, it opens its window when Assetto Corsa's start menu closes, and a message says where to find it again: "move the mouse to the right edge of the screen: CSP's app bar slides out; click the AC DLSS-G logo there". The flag is kept in CSP's app storage. While the bridge passes the game through or does not run (for example after another mod replaced the install, GitHub issue 11), a message says why once per session, with a button that opens the window, unless the window is open anyway. CSP builds without these messages get CSP's plain message instead.
- **The MSAA reason says where MSAA is on** (Nexus: "unavailable: MSAA" although it was off). The window now names the value and the file the bridge read at game start, and where to turn it off: "MSAA is on: AASAMPLES=4 in C:\Users\<you>\Documents\Assetto Corsa\cfg\video.ini (read at game start); set Anti-aliasing to Off in Content Manager > Settings > Assetto Corsa > Video". MSAA keeps frame generation off in every DLSS mode, not only with DLAA, as the READMEs said before. `bridge.log` gives the sample count of the game's swap chain, and logs the game's legacy `CreateSwapChain` (which CSP uses with MSAA) at INFO.
- **VR: ac-dlssg switches itself off.** When Assetto Corsa starts in VR (`video.ini` `[CAMERA] MODE` `OPENVR` or `OCULUS`, or CSP's OpenXR mode `__EXT_OPENXR`), the bridge starts nothing: no Streamline, no MFG-Unlocker and no camera section. It passes the game through, and the AC DLSS-G window says "VR (MODE=OPENVR): DLSS Frame Generation works only on a monitor, not in a headset; ac-dlssg stays off in VR". VR is not supported and not planned: frame generation runs in the swap chain that shows the game on the monitor, while the headset gets its frames from SteamVR, the Oculus runtime or OpenXR. The other camera modes are named for what they are ("camera mode TRIPLE (triple screen) is not supported", "custom rendering mode __EXT_360 (360, fisheye or split screen) is not supported"), and the CSP app also reports CSP's OpenXR mode as VR and its custom rendering modes, frame by frame.
- **Another mod's DLSS hook is left alone.** Before the bridge hooks CSP's NGX functions it now checks whether another mod already hooked them (a first instruction that jumps out of NVIDIA's module: MinHook's 5-byte jump, or the 14-byte jump of DLSS 5 Bridge 1.4.12). Hooking over such a hook could crash the game at the first DLSS call of a session; such a module is not hooked now, and `bridge.log` names where the other hook leads. DLSS 5 Bridge's old file name `dlss5-dx11-bridge.addon64` counts as DLSS 5 Bridge too.
- The AC DLSS-G window says plainly that the third-party DLSS 5 Bridge and RenoDX DLSS5 add-ons cannot run together with ac-dlssg yet, and that CSP's built-in Neural Rendering can: "DLSS 5 Bridge (dlss5-bridge.addon64) cannot run together with ac-dlssg yet. Use CSP's built-in Neural Rendering instead, which works with ac-dlssg, or remove the add-on for frame generation." (RenoDX DLSS5 gets the same text with its name). Before, it only said "dlss5-bridge.addon64 is loaded". The bridge still passes the game through while one of them is loaded.
- **The NVIDIA App's DLSS override is a note, not a warning, when it does no harm** (GitHub issue 10). Streamline reads its override setting (0x10E41E06) from the game's profile first, and the global value only when the game's profile has none; the bridge now does the same, so a global override under the game profile's 0 no longer warns. The DLSS-FG override (0x10E41E03, read from the game's profile, else the global one) makes NGX load the NVIDIA App's newer DLSS-G from its cache instead of the one in `ac-dlssg\sl`: on an RTX 50, and on an RTX 40 without MFG-Unlocker, that works, and the AC DLSS-G window shows the note "Note: the NVIDIA App's DLSS override is on, so DLSS-G may use the App's newer model. This is normal, not an error." in grey. It stays a warning on an RTX 20 or RTX 30 (dlssg_for_sm86) and on an RTX 40 with MFG-Unlocker, which both work only with the DLSS-G they were made for. "DLSS-G override mode: frame generation forced off" stays a warning.
- The "DLSS-G provider" line of `bridge.log` names the NVIDIA App's DLSS-G from NGX's cache (`\NGX\models\dlssg\versions\<n>\files\*.bin`, with its version, for example 310.9.16) and the driver's own `nvngx_dlssg.dll` from the DriverStore, which NVIDIA Smooth Motion loads, instead of saying "nvngx_dlssg.dll is not loaded".
- `bridge.log` keeps the diagnostic lines of the 1.2.1 test build for GitHub issue 10: `diag:` lines say who creates the swap chains and who calls Present and NGX, describe the devices, windows and modules involved and list the driver profile's settings, and the stats line ends with `no_evaluate=<n>`.

### Documentation

- The READMEs, the install guides and the test package's `README-test.txt` explain the installer's NVIDIA Smooth Motion step: what it changes and why, the Windows prompt, `-KeepSmoothMotion`, that the uninstaller restores the setting, `ac-dlssg-drs.exe smooth-motion status`, and the steps in NVIDIA Profile Inspector for anyone who prefers to do it by hand. `README-test.txt` gives the helper's SHA-256, and the release notes list it next to the DLL's.
- **Triple screens: help wanted.** The READMEs and `README-test.txt` ask owners of three monitors to set `triple_diag=1`, drive a minute in triple-screen mode with CSP's Extra FX and its "Allow in triple" on, and send the `collect-logs.bat` zip, since those logs decide whether and how frame generation can work there; AC's triple-screen mode also runs in a window on one monitor.
- The READMEs, the install guides and the test package's `README-test.txt` say that MSAA must be off in every DLSS mode (before, they asked for it only with DLAA), that CSP's DLSS preset M removes ghost trails at night and behind lights, and where CSP's app bar and the AC DLSS-G window are (move the mouse to the right edge of the screen).
- New entries under "If something goes wrong": NVIDIA Smooth Motion, with the steps in NVIDIA Profile Inspector ("Smooth Motion - Enabled APIs", 0xB0CC0875, set to 5 in the "Assetto Corsa" profile, and the global profile checked too); VR, which is not supported and not planned, with SteamVR Motion Smoothing, Meta ASW or OpenXR reprojection instead; neural rendering: CSP's built-in Neural Rendering works together with ac-dlssg, while the DLSS 5 Bridge and RenoDX DLSS5 add-ons cannot yet; and the Streamline warnings that appear once at start or after frame generation switches off and are harmless. `OLD_SWAPCHAIN=1` is listed as not supported.

## [1.2.0] - 2026-10-22

### Added

- **3X and 4X on RTX 40 through MFG-Unlocker** (GitHub issue 2). NVIDIA allows DLSS Frame Generation 2X on RTX 40 and enables 3X and 4X only on RTX 50. On a PC whose NVIDIA GPUs are all RTX 40 (no RTX 30 and no RTX 50 next to them), the installer now prints a notice and downloads the third-party [MFG-Unlocker](https://github.com/dashdogy/MFG-Unlocker) by dashdogy, which lifts that limit (unofficial): the release asset `MFGUnlocker-v1.5.0-hotfix.1.zip` of tag v1.5.0-hotfix.1 from the author's GitHub release, checked against its pinned size and SHA-256, and the SHA-256 of `MFGUnlocker.dll` in it. That release is 1.5.0 plus only the fix for video memory that was lost each time frame generation was set up again (upstream pull request 80); the 1.5.0 copy of an earlier 1.2.0 test build is replaced on the next install. Only that DLL is kept, as `<game>\ac-dlssg\mfg\version.dll`, never next to `acs.exe`. The notice says that it is a third-party project by dashdogy and not an NVIDIA project, that its code is under MIT and it contains Intel XeSS-derived data under Intel's terms, that it lifts NVIDIA's RTX 50-only restriction (section 4.d of the NVIDIA RTX SDKs License) by patching NVIDIA's DLSS-G code in memory (no file on disk is changed), that its own Backspace menu should stay on "Follow game", and that the game may load slower. `install.bat -NoMfgUnlocker` installs without it and removes the copy an earlier install put there.
- The bridge loads it by full path at start, before Streamline, only with `enabled=1` and the new `mfg_unlocker=1` (the default; the installer writes it), only the pinned file, only when the GPU the game renders on is an RTX 40, and never next to dlssg_for_sm86. `bridge.log` logs the load with its time in ms and its file version, and later the loaded DLSS-G provider (`nvngx_dlssg.dll`) with its path and version, and whether 3X/4X were unlocked.
- A failed MFG-Unlocker download or a hash mismatch is a warning: everything else is installed, and frame generation stays at 2X. An MFG-Unlocker you installed yourself (a proxy DLL next to `acs.exe` that exports `MfgUnlockSingleModuleQuery`, or its older file names) is left alone, and the installer does not add its own copy next to it.
- On an RTX 40 without MFG-Unlocker, the dimmed 3X and 4X buttons and the multiplier note say "NVIDIA enables 3X/4X only on RTX 50". With it, the GPU line under Details says ", RTX 40 via MFG-Unlocker (unofficial)", or ", MFG-Unlocker loaded but did not unlock" when Streamline still allows 2X only. The 4X cap and the clamp to what Streamline allows stay.
- The uninstaller removes MFG-Unlocker (only while it is the file installed), and `uninstall.bat -RemoveData` also deletes its settings next to `acs.exe` (`RTXMFG-Universal.json`, `RTXMFG-Universal.status.json`, `RTX40MFG-UI.ini`, `RTX40MFG-UI-layout.ini`) and its logs in `%TEMP%` when the installer put it there, also after a later `install.bat -NoMfgUnlocker` or a GPU change removed that copy again (the manifest remembers it). `collect-logs.bat` collects them. The install manifest records it (schema 6); schema 5 manifests upgrade without a step.
- **RTX 20 through dlssg_for_sm86** (GitHub issues 4 and 5). A tester confirmed 2X, 3X and 4X on an RTX 2070 SUPER: 52 real fps became 104 at 2X, 43 became 130 at 3X and 39 became 156 at 4X. dlssg_for_sm86's README says that its release 0.3.1 and newer run DLSS-G on RTX 20 (Turing) with the same stock `dlssg_sm86.ini` as on RTX 30, and its author tested an RTX 2080 Ti with 0.3.x. The installer now installs the pinned dlssg_for_sm86 0.3.5 on RTX 20 too: a Turing chip with tensor cores (a device ID of TU102, TU104 or TU106) whose name contains "RTX", that is the RTX 2060 to 2080 Ti with their Super models, laptop GPUs, TITAN RTX and Quadro RTX. It says "RTX 20 via dlssg_for_sm86 (experimental)" and asks for a report with the `collect-logs.bat` zip, and the GPU line of the AC DLSS-G window says the same. GTX 16 cards (also the GTX 1660 SUPER and GTX 1650 built on TU106), MX and T-series GPUs have no tensor cores and no DLSS; the installer says that they are not supported. A TU102, TU104 or TU106 ID whose name does not say RTX, as an RTX 20 before the NVIDIA driver is installed ("Microsoft Basic Display Adapter"), gets no dlssg_for_sm86 either; the installer says to install the driver and run `install.bat` again. The rules for PCs with several GPUs stay: no dlssg_for_sm86 next to an RTX 40 or RTX 50, and MFG-Unlocker only when every NVIDIA GPU is an RTX 40. Frame generation stays clamped to what Streamline allows and to 4X.

### Changed

- The RTX 2050 is an Ampere chip (GA107, SM86) despite its name (GitHub issue 8): a tester ran 2X, 3X and 4X on an RTX 2050 laptop, first with their own test build based on 1.1.1 and then with the 1.2.0 test build. It always got dlssg_for_sm86 by its device ID; the installer and the window now say "RTX 30 or RTX 2050 (Ampere SM86)" where they said RTX 30.

### Fixed

- A `version.dll` in the game folder is identified before the bridge calls it dlssg_for_sm86: by the pinned SHA-256, as MFG-Unlocker by its export, or as unknown. Before, any `version.dll` that Windows 10 loaded from the game folder (also a user's MFG-Unlocker) was logged and shown as "dlssg_for_sm86 loaded". `spoof_load_any=1` never loads MFG-Unlocker as the spoof.

### Documentation

- The READMEs, the install guides, the test package's `README-test.txt` and `THIRD_PARTY_NOTICES.txt` describe NVIDIA's 2X limit on RTX 40 and MFG-Unlocker, what it downloads and changes in the game folder, and how to leave it out or remove it. The earlier texts said that 3X and 4X run only on RTX 50 and on RTX 30.
- They list RTX 20 as supported through dlssg_for_sm86, GTX 16, MX and T-series cards as not supported, and the RTX 2050 as an Ampere chip. The README's "Looking for an RTX 20 tester" section is now "RTX 20": it thanks the testers and says that no more are needed (the old links still lead there). The help-wanted badge is gone, and the NVIDIA badge lists RTX 20.

## [1.1.1] - 2026-10-13

### Fixed

- **"camera: not written" on older CSP previews** (GitHub issue 1). On CSP 0.3.0-preview445 the AC DLSS-G app stopped at load with `'struct state_sim' has no member named 'renderSize'`, so it never sent the camera to the bridge and frame generation stayed off. The app now checks once which camera-related fields the installed CSP has (`renderSize`, `originShift`, `cameraJumped`, `driveableCameraMode`, `carCameraIndex`, `trackCamerasSet`, `isTripleMode`, `isVRConnected`, `cameraClipNear`, `cameraClipFar`) and uses a fallback for the missing ones: the window size instead of the render size, no origin shift, and AC's usual clip planes. It logs one warning that names them in the CSP log.

## [1.1.0] - 2026-09-30

### Changed

- **A new AC DLSS-G window.** It is drawn in the ac-dlssg colours, dark with a red accent, and has the logo in its header. It has:
  - a status pill that says whether frame generation runs;
  - an animated on/off switch;
  - 2X / 3X / 4X as one control with a sliding highlight;
  - an FPS card with the real and the shown frames;
  - a video memory bar that turns amber and then red as the memory runs out;
  - a Details section that opens smoothly.
  Numbers and bars move smoothly instead of jumping. The settings, the notes and what the buttons do are the same as in 1.0.0.
- The window has its own icon in CSP's app bar.
- **Save as default** shows "Saved" only when the bridge confirms that it wrote `ac-dlssg.ini`. A failed save is shown in red under the button.
- The mouse wheel over the open Details section scrolls the window.
- **The unpacked folder is not needed after the install.** The installer puts `uninstall.bat` and `collect-logs.bat` into the game folder's `ac-dlssg` folder, with the scripts they run in `ac-dlssg\scripts`, so the unpacked folder and the zip can be deleted. They are recorded in the install manifest like every other file (schema 5): an upgrade replaces them, a failed install rolls them back, and an upgrade over 1.0.0 adds them.
- The `uninstall.bat` in the game folder works on that game folder without looking up Steam, takes the same options (`-RemoveData`), asks for administrator rights when the game folder needs them, and after the Enter at its end removes itself, `collect-logs.bat` and `scripts`. With `-RemoveData` the whole `ac-dlssg` folder goes; without it the logs and `ac-dlssg.ini` stay. If its window was closed at that Enter, running it again says that ac-dlssg is already uninstalled and removes what is left of it.
- The `collect-logs.bat` in the game folder writes its zip into `ac-dlssg` and prints the zip's full path. The system report no longer leaves a folder next to the scripts.
- **An update does not download Streamline again.** When each Streamline 2.14.1 file in `ac-dlssg\sl` matches its pinned SHA-256 and every DLL carries NVIDIA's signature, the installer uses them and says "Streamline 2.14.1 is already installed and verified; not downloaded again". A changed or missing file means a download as before. dlssg_for_sm86 on RTX 30 works the same way: pinned `version.dll` and `dlssg_sm86.ini` are not downloaded again, a missing one is. Any other `version.dll`, also one put over the installed one since, is still left alone with a warning.

### Fixed

- Upgrading or uninstalling a ReShade-mode install in a game folder whose path has Cyrillic or other non-ASCII letters works: the install manifest is now read as UTF-8. Before, the upgrade refused because "the first install edited" another ReShade.ini, and the uninstall because "ReShade would still load ac-dlssg.dll".

### Documentation

- The install guides and READMEs say that the unpacked folder can be deleted after the install, that the uninstaller and the log collector are in the game folder's `ac-dlssg` folder (in Steam: right-click Assetto Corsa, Manage, Browse local files), and that an update does not download Streamline again.
- The logo, a README header with it, and a square cover for the Steam guide (`docs/logo`, drawn by `tools/brand/make_logo.py`).
- The install guides now say to turn on DLSS in CSP before the first start. With DLAA they also say to turn off MSAA and FXAA in the game's video settings, since either of them with DLAA leaves a ghost trail behind moving things.

## [1.0.0] - 2026-09-29

The first release. ac-dlssg brings NVIDIA DLSS Frame Generation (DLSS-G) to
Assetto Corsa with Custom Shaders Patch (CSP). The game keeps rendering in
DirectX 11. Every finished frame is presented through a DirectX 12 swap chain
created with NVIDIA Streamline 2.14.1, where DLSS-G adds the generated frames.
Depth and motion vectors come from the DLSS upscaling pass that CSP already
runs, and the camera comes from the CSP Lua app `AcDlssg` that the installer
adds.

### Features

- **DLSS-G 2X, 3X and 4X through Streamline.** 2X is the default. `fg_multiplier=3` or `4` in `ac-dlssg.ini` asks for two or three generated frames per real frame. Streamline allows that when it reports more than one generated frame: on RTX 50 natively, and on RTX 30 through dlssg_for_sm86. RTX 40 stays at 2X. A request above what Streamline allows is lowered to its maximum and logged once.
- **NVIDIA Reflex Low Latency** and the PCL latency markers, through Streamline.
- **Automatic on and off.** Frame generation turns on by itself once CSP's DLSS runs, and it stays off in the pause menu and the main menu. Ctrl+F10 (the `hotkey` key) switches it on and off for an A/B comparison.
- **The AC DLSS-G window** in CSP's app bar, in both install modes. It has the same switch, and it shows why frame generation is off (or "On, but paused" while Streamline pauses it for an unfocused game window), the real and output fps, the bridge's GPU time, the video memory used and its budget, the GPU and the dlssg_for_sm86 state. Its 2X, 3X and 4X buttons change the multiplier at once (the ones the GPU or driver does not allow are disabled), it warns when video memory is tight, and it says when a saved setting applies only after a restart. **Save as default** writes the current switches, including `fg_multiplier`, into `ac-dlssg.ini` key by key and keeps every other byte.
- **ReShade mode and standalone mode.** With ReShade 6.8 or newer (the add-on build) installed as `dxgi.dll`, ReShade loads the bridge as its `ProxyLibrary`. Without ReShade, the bridge itself is the game folder's `dxgi.dll`. The installer picks the mode.
- **Laptops with Optimus**, where the NVIDIA GPU renders and the integrated GPU drives the panel. Hardware-accelerated GPU scheduling is read per adapter through D3DKMT, with the registry value only as a fallback. A swap chain on a non-NVIDIA adapter passes through, and the reason names the Windows graphics preference and CSP's `SELECT_ADAPTER`. On Windows 11 25H2, which binds `acs.exe`'s `VERSION.dll` import to System32, the bridge loads the pinned dlssg_for_sm86 `version.dll` by full path.
- **Video memory guard.** Before DLSS-G is first enabled, and whenever the multiplier changes, the bridge asks Streamline how much video memory DLSS-G needs. DLSS-G stays off while that estimate plus the headroom does not fit into the budget, and a 3X or 4X that does not fit falls back to 2X with a log line. `fg_vram_headroom_mib=auto`, the default, adapts the headroom to the GPU (none below a 6 GB budget, 256 MiB above) and still turns 2X on when only a little is missing, with a warning in the window; a larger shortfall keeps DLSS-G off with a reason that says what to lower. A number sets a fixed headroom; when that number is what keeps DLSS-G off and `auto` would let it run, the bridge switches to `auto` at once, saves it in `ac-dlssg.ini` and says so in the window. The window shows the reason and the video memory.
- **Pass-through.** When frame generation cannot run (no supported GPU, missing files, unsupported CSP settings or a failed Streamline start), the bridge passes through and the game runs as it does without the mod. With `enabled=0` Streamline is never loaded.
- **Logs.** `<game>\ac-dlssg\logs\bridge.log` has a start banner with the versions and the decisions, one statistics line per second and every state change; the previous run's log is kept as `bridge.prev.log`. `ac-dlssg.ini` warns about a key that appears twice and names the value it used.
- **Automatic installer.** Double-click `install.bat`; it asks nothing. It finds the game through Steam, starts itself again with administrator rights when the game folder needs them, downloads Streamline 2.14.1 from NVIDIA's GitHub release and checks its SHA-256 and NVIDIA's signatures, and prints where NVIDIA's license files are.
- **dlssg_for_sm86 on RTX 30.** On an RTX 30 GPU (desktop or laptop) the installer prints a notice about [dlssg_for_sm86](https://github.com/sdli1995/dlssg_for_sm86) by sdli1995, then downloads exactly `version.dll` and `dlssg_sm86.ini` of release 0.3.5 (commit `9621db5`) from the author's repository, checks their git hashes and the SHA-256 of `version.dll`, and puts them next to `acs.exe`. A `version.dll` that is already there is never replaced. `install.bat -NoSpoof` installs without it.
- **Journaled install, upgrade and uninstall.** Every change is recorded before it is made and rolled back when the install fails. Running `install.bat` of a new package over an earlier install upgrades it without questions: it replaces the old build's files, removes the ones the new build no longer ships, and switches between ReShade and standalone mode when ReShade was added or removed. It stops only for files that are not this project's, such as another mod's `dxgi.dll`. It also replaces the old default `fg_vram_headroom_mib` blocks an earlier build wrote into `ac-dlssg.ini` with `auto`, and keeps a value the user set. `tools\uninstall.bat` restores every file the installer changed; `-RemoveData` also deletes the logs and settings. `tools\collect-logs.bat` zips the logs for a bug report and only reads files.
- **No re-hosted files.** The release zip holds no NVIDIA file and no dlssg_for_sm86 file; both are downloaded on the player's PC. `docs\` in the zip carries both READMEs, the GPL-3.0 license, `EXCEPTIONS.md` and `THIRD_PARTY_NOTICES.txt`.
- **Verifiable builds.** GitHub Actions builds the release. The zip and `ac-dlssg.dll` have build provenance attestations, and the release notes list their SHA-256.

### Requirements

- Assetto Corsa from Steam with a Custom Shaders Patch preview build (0.3.0-preview or newer), available from CSP's author on [Patreon](https://www.patreon.com/c/x4fab/home), with CSP's DLSS upscaler turned on (any quality mode, including DLAA).
- An NVIDIA RTX 40 or RTX 50 GPU, or an RTX 30 GPU with dlssg_for_sm86, which needs driver R580 or newer. RTX 20 is not supported.
- Windows 10 version 2004 or newer, or Windows 11, with hardware-accelerated GPU scheduling on. On laptops, `acs.exe` must be set to "High performance" in the Windows graphics settings.
- Internet on the first install, for Streamline (about 276 MB) and, on an RTX 30, dlssg_for_sm86 (about 30 MB).

### Known limitations

- No HUD-less colour buffer: CSP app windows and on-screen UI can show small artifacts during fast motion.
- Not supported: VR, triple screens, HDR output, MSAA, `OLD_SWAPCHAIN=1`, `EXCLUSIVE_FULLSCREEN=1` and letterboxed output (a `video.ini` aspect ratio that differs from the window while `ALLOW_STRETCHING=0`).
- Other CSP upscalers (FSR, XeSS) do not provide the inputs frame generation needs.
- No multi frame generation above 4X and no dynamic multi frame generation.
- CSP's FPS counter shows the real frames only; the NVIDIA overlay (Alt+R), RTSS or another external counter shows the frames on screen.
- On a 4 GB card video memory is tight: if the game stutters, lower CSP's texture or shadow quality.
- dlssg_for_sm86 has no LICENSE file, embeds NVIDIA's `nvngx_dlssg.dll`, and using it on RTX 30 circumvents a technical limitation that section 4.d of the NVIDIA RTX SDKs License forbids for that license's licensees. Whether to use it is the player's decision.

### Tested on

- **Desktop, ReShade mode:** Intel Core i9-9900, GeForce RTX 3080 10 GB (driver 616.64), 16 GB DDR4-3600, Windows 10 22H2, CSP 0.3.0-preview622, ReShade 6.8.0, dlssg_for_sm86 0.3.5. DLSS-G 2X doubled the frame rate with no ghosting and no blur, and a 15-minute session had no crash or freeze.
- **Laptop, standalone mode:** Acer Nitro 5 AN515-57, GeForce RTX 3050 Ti Laptop GPU 4 GB (driver 610.88), Core i5-11400H, 32 GB RAM, Windows 11 25H2, Optimus (the Intel iGPU drives the panel), no ReShade, CSP preview634, dlssg_for_sm86 0.3.5. DLSS-G 2X turned 31 real fps into 60 on screen, and 30 into 57 in a tunnel.
- 3X and 4X are covered by the unit tests and the test app; on the RTX 3080, dlssg_for_sm86 ran 3X and 4X in a native DLSS-G game before this project started.
