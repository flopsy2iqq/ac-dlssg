# ac-dlssg M3 record: capture, camera and DLSS-G 2X

**Goal:** DLSS-G 2X in Assetto Corsa on the RTX 3080 (and later the laptop)
through dlssg_for_sm86, using CSP's own DLSS inputs and a CSP Lua camera app.

**Spec:** `docs/superpowers/specs/2026-09-28-ac-dlssg-bridge-design.md`
(sections 6.4-6.8, 6.11, 7, 8, 9).

M3 was built directly on branches at the user's request, in two phases. Full
agent reports, with every decision and verified fact, are kept outside the
repository in `.work\notes\m3-phase1.json` and `m3-phase2.json`.

## Phase 1: four independent units

| Unit | Files | Tests |
|------|-------|-------|
| Camera section, reader and Lua app | `src/camera_layout.h`, `src/camera_channel.*`, `apps/lua/AcDlssg/` | 25, including a 3,000,000-read torn-snapshot race and a check that the Lua layout string matches the C++ struct |
| Frame constants | `src/frame_constants.*` | 25 closed-form matrix tests |
| NGX hook | `src/ngx_params.h`, `src/inline_hook.*`, `src/ngx_hook.*`, `tests/fake_nvngx/` | 11 + 7, against a fake NGX DLL |
| Capture slots | `src/capture_slots.*`, `shaders/depth_blit.hlsl` | 24, with readback on D3D11 and D3D12 |

Each unit was built test-first in its own worktree, reviewed adversarially,
and merged into `m3`.

## Phase 2: integration

- **NGX hook fixes.**
  - The loader-notification callback is lock-free.
  - A detour with no original returns `0xBAD00000`.
  - A zero subrect falls back to the input size.
  - CSP's DLSS NR (`nvngx_dlssnr.dll`, feature ids 16-20) and DLSS RR are never counted.
  - Reused module bases are detected.
  - `SetSink` waits for calls in progress.
- **Core.**
  - `src/capture_coordinator.*` is the NGX sink: it latches the camera once per frame, copies into the slot and handles the refusal paths.
  - `src/fg_policy.*` holds the per-frame DLSS-G gate, the reasons, the VSync rule, the video memory guard and the status poll.
  - `StreamlineRuntime` gains the DLSS-G options, state, tags and constants.
  - The presenter tags depth and motion vectors every frame and sets the constants.
  - The Ctrl+F10 hotkey toggles DLSS-G. A resize or fullscreen change turns DLSS-G off and presents once with it off first.
- **Configuration.** New keys: `camera_flip_handedness`, `camera_negate_side`, `proxy_without_fg` (default 0: an unsupported GPU passes through), `tag_without_fg` and `fg_vram_headroom_mib` (default 512).
- **Tooling.**
  - The test app gains `--fake-ngx` and `--fake-camera`, and the new scenarios are `fg-pipeline`, `fg-pipeline-resize`, `fg-no-camera` and `fg-unsupported-passthrough`.
  - The dev scripts and the test package install the Lua app into `<game>\apps\lua\AcDlssg`.
- **Review.** Three lenses (the Streamline API, synchronisation and lifetime, and in-game behaviour) found 16 findings, one of them critical. The fix pass handled them as described below.

Final state (commit 9f47118 plus this record): 362 unit tests and 34 test app
scenarios pass in Debug and Release, 324+ dev-script checks pass, and the
imports are still only ADVAPI32, KERNEL32, ole32, SHELL32 and USER32. DLSS-G
itself cannot run in automated tests without the spoof, so the in-game check
is the real test.

## Rulings

- **The capture does not signal the shared fence.** A capture value is always
  higher than the value D3D11 waits for at the next Present, so it released
  CSP's queue early. The Present's signal V comes after the capture copy on
  the same context and covers it. The spec is updated (6.4, 6.5, 7).
- **No `slFreeResources` after DLSS-G is switched off.** The bridge keeps
  `eRetainResourcesWhenOff`, because freeing brings back DLSS-G re-creation,
  which crashed an RTX 3080 in dlssg_for_sm86 issue #598. If this is wrong,
  the laptop keeps about 272 MB at 1080p after a hotkey-off. Revisit on the
  laptop.
- **The generated frame count** is taken from `slDLSSGGetState` after every
  DLSS-G Present, as `max(n, 1) - 1`. This works under either reading of
  `numFramesActuallyPresented`. The first three raw values are logged so the
  reading can be confirmed in game.

## Deferred

- A stall followed by a resize can skip the extra Present with DLSS-G off.
  This is an error path only.
- A slot is reused without a CPU progress check. GPU ordering covers it,
  except right after the watchdog's forced release of a stall of 500 ms or
  more, which risks one bad generated frame.
- The slot textures are kept after DLSS stops being called, which costs about
  200 MB at a 4K render size. The cached source views are released.
- Cosmetic: the first creation of each slot is logged as "recreated".

## In-game result (2026-09-29, RTX 3080, ReShade mode, dlssg_for_sm86)

**Passed.** The user reports frame generation working well: presented fps
doubled, no ghosting, no blur, the image unchanged, and no crash or freeze in
a 15-minute session.

The bridge log confirms it:

- DLSS-G turned on 11 s after the first capture and stayed on in 885 of 929
  stats lines.
- Captures, fresh camera snapshots and tagged frames matched the base rate
  (about 51 per second at 52 fps).
- Stalls, PCL problems and double evaluates were all 0.
- DLSS-G turned itself off in the pause and in-game menus.
- CSP's inputs were depth R32_TYPELESS and motion vectors R16G16_FLOAT, both
  1707x960 for a 2560x1440 output, with create flags 0x2 and MV scale
  -1707,-960, as spec section 4 predicted.

Two fixes came out of the in-game runs:

- **The NGX filter rejected CSP's real DLSS feature.** CSP 0.3.0-preview622
  sets `DLSSNR.Hint.Render.Preset` on its SuperSampling create block. Scalar
  NR keys are now only logged; NR and RR are still excluded by feature id and
  module.
- **One run ended during the track load** with CSP's "Physics calculations
  got stuck". CSP's minidump showed no thread in the bridge, and the run never
  reached a capture. It did not happen again. Bounded step tracing at
  `log_level=debug` is kept so a repeat shows the exact step.

Open for later:

- `numFramesActuallyPresented` read 1 on the first DLSS-G Presents, so the
  `generated=` average (33) is below `fg_frames` (51). The user saw the full
  2x, so this is a counting detail.
- Streamline warns about the resource alignment of its own
  `dlfg-output` clone.
