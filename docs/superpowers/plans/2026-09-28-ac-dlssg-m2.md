# ac-dlssg M2 record: Streamline, Reflex and PCL

**Goal:** present every CSP frame through a Streamline proxy swap chain with
Reflex low latency and PCL markers, DLSS-G still off. M3 turns DLSS-G on.

**Spec:** `docs/superpowers/specs/2026-09-28-ac-dlssg-bridge-design.md`
(sections 6.4, 6.8, 7, 8, 12).

This is a record of what was built, not a step-by-step plan: M2 was built
directly on the branch at the user's request, with one review pass at the end.

## Result on the RTX 3080 (no spoof)

- Streamline initialises and reports no errors. Reflex low latency is
  available.
- DLSS-G reports `eErrorNoSupportedAdapterFound`, as expected without
  dlssg_for_sm86. Streamline logs three warnings for it, and they are benign.
- 120 frames with markers produced 0 PCL problems.
- 159 unit tests pass in Debug and Release. All 11 test app scenarios pass in Debug and Release, and
  the bridge costs about 0.04 ms of GPU time per frame (budget 0.5 ms).

## Decisions taken during the build

- A disabled bridge (`enabled=0`) never loads Streamline, so the game runs as
  it does without the mod.
- RenderSubmitEnd is sent with PresentStart just before the D3D12 Present,
  not right after the D3D11 fence signal as spec section 7 says. The D3D12
  copy is recorded between those two points.
- A frame dropped by the stall path stays open until the next delivered
  Present, so no frame is abandoned.
- A failed Streamline initialisation is a WARN. The game then runs without
  the bridge.
- After Streamline has shut down, every new swap chain passes through with the
  reason "Streamline already shut down". Streamline allows one lifetime per
  process.
- dev-install `-Force` also covers Streamline files that were changed outside
  the script, and keeps a backup of them. Only the `bin\x64` license files go
  to `ac-dlssg\sl`. The release installer (M4) adds the root `license.txt`.
- `sl:` warnings in test app logs are notes. `sl:` errors fail a scenario.

## Review (one pass)

- Fixed, medium: a presenter creation failure after `slSetD3DDevice` released
  the device without `slShutdown`. The runtime is now shut down first. A child
  test covers this.
- Fixed, low: `StreamlineRuntime` state flags read without the lock are now
  atomic.
- To check in game: when CSP releases its swap chain only at process exit,
  `bridge.log` must still end with the `slShutdown` line and the game must
  exit promptly.

## In-game check (next)

Install with `tools\dev-install.ps1`, which now also copies the Streamline
DLLs to `<game>\ac-dlssg\sl`. Then check:

1. The game starts and renders as in M1.
2. `bridge.log` shows "Streamline: initialised from", "Streamline: Reflex low
   latency on", the proxy chain line, and `streamline=on reflex=on
   pcl_problems=0` in the stats lines.
3. The frame rate matches M1 within noise.
4. On exit, the log ends with "Streamline: slShutdown" and the game closes
   promptly.
